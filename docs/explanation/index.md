# Explanation

**Understanding-oriented** — why Grow is designed this way, and what the trade-offs are.

## Contains

- Architecture rationale, design trade-offs, historical background, conceptual clarification.
- Readable in any order, centred on "why".

## Does Not Contain

- Step-by-step procedures → `../tutorials/` `../how-to/`
- Facts to look up → `../reference/`
- A single frozen decision → `../architecture/` (ADR)

## Boundary

Explanation vs. ADR: an ADR records **one specific decision** and its alternatives;
explanation covers the **whole design space** around it. An ADR is an archive; an
explanation is an article.
