# Design

**Read this in other languages:** [English](README.md) | [简体中文](../../../zh-CN/framework/design/README.md)

*Design record* — one settled design per file.

A design record explains one part of the framework once its approach has settled: the problem it
solves, how it works, and the trade-offs that shaped it. It is written for someone reading the
framework, not as a log of the discussion that produced it, and it is revised when the design itself
changes.

What belongs here:

- a design that has settled, one file per topic.

What does **not** belong here:

- a design still in motion — it is a draft and stays outside the repository, so that no half-formed
  proposal is mistaken for a decision;
- the deliberation that produced a decision — a decision record is not a design record, see
  [`../../repository/documentation/documentation.md`](../../repository/documentation/documentation.md);
- terms and definitions — see [`../reference/glossary.md`](../reference/glossary.md).

Naming follows
[`../../repository/documentation/conventions.md`](../../repository/documentation/conventions.md).
